# Golden-set scoring regression

**What passing this proves:** the executor is self-consistent and free of
regressions. Every fixture in `papers/` is scored end to end and checked
against expected marks recorded independently of the code that produces them,
so a change to marking behaviour shows up as a failure here.

**What passing this does not prove:** anything at all about agreement with a
real answer key. That requires released papers with official keys, and until
those exist the corpus is synthetic.

The two are different claims and the suite reports which it is making. Every
run prints its official and synthetic fixture counts; a run with zero official
papers is not a validated one, and the milestone Definition of Done carries
"golden set validated against real released papers" as **failed-blocked** until
that count is three (DEC-2).

## Fixture rules

- `provenance` is `official` or `synthetic`, and the loader enforces the
  difference. A synthetic fixture must carry `synthetic` in its filename and
  its `paperId`, and must not claim a session, a paper code, or any field that
  would let it be mistaken for a real NTA paper.
- An `official` fixture must cite its source. A key nobody can trace back is not
  an official key.
- Expected marks are the answer key's verdict, written down independently. A
  fixture generated by running the executor tests nothing.

## Adding a real paper

Drop the JSON in `papers/`. No code changes: the loader validates it, the
regression suite picks it up, and the reported official count goes up.
